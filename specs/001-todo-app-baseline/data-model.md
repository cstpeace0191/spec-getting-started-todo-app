# Data Model: Todo App Baseline

**Feature**: [spec.md](spec.md) | **Research**: [research.md](research.md)

## Entity: Task

A single item on the shared list.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| `id` | UUID v4 string | Yes | Generated by the server on create. Unique across all tasks. Never changes. |
| `name` | text (unbounded) | Yes | Non-empty after trimming whitespace (FR-005). No maximum length (FR-015). |
| `completed` | boolean | Yes | Always `false` on create (FR-006). Toggled by the user (FR-008). |

**Relationships**: None. There is one flat list.

**Lifecycle**:

```text
created (completed = false)
   ├── toggle ──▶ completed = true  ◀── toggle ──┐
   │                 └────────────────────────────┘
   └── delete ──▶ removed (terminal)
```

- **Create**: Insert with `completed = false` and a new server-generated `id`.
- **Toggle**: Flip `completed`. Only the `completed` field changes through this path.
- **Delete**: Remove the row. Deleted tasks do not reappear after reload (User Story 3).
- **Rename**: Not exposed in the UI (spec Edge Cases). The API may accept `name` on update, but the
  UI does not use it.

## Storage mapping

| Field | MySQL | SQLite |
|-------|-------|--------|
| `id` | `CHAR(36)` primary key | `TEXT` primary key |
| `name` | `TEXT` (unbounded, per Decision 5) | `TEXT` |
| `completed` | `BOOLEAN` (`TINYINT(1)`) | `INTEGER` (0 or 1) |

The `todo_items` table is created automatically at server start (requirements feature 6).
